한눈에

목표는 둘이 하나로 묶인 라운드다. 무대: ../Backlot의 영화 세트(FBX 124개, 인스턴스 1488, 이미지 쿼드 179, 조명 31, 컷 8, 라이팅 키 4)를 엔진이 읽어 표준 파이프라인으로 그린다. 에디터: 직접 쓰는 확인 도구 — 클릭 선택, 계층, 인스펙터, 기즈모, 일시정지·스텝, 장면 다시 읽기 — 를 모든 동작이 포트의 속성 쓰기와 같은 길로 가게 만든다. Unity와의 비교는 배치만, 스타일은 비교하지 않는다.

지금까지: 무대가 엔진 안에 섰고, 8컷 × 4키가 Unity와 같은 자리에 놓인다. 에디터는 완성됐다. 클릭·계층·포트로 고르고, 인스펙터와 기즈모로 고치고, 장면 파일을 다시 읽고, 장면 시간을 멈추고 돌린다. 사인과 게임 아틀라스는 투명 텍셀을 잘라내고, 잘린 모양대로 그림자를 드리운다. 8컷의 낮과 밤이 골든으로 고정됐고, Unity와의 배치는 가장자리로 잰다. 남은 것은 G2다.

이 라운드가 도는 방식

  • 자율. 증분 하나가 끝나면 브랜치 editor-stage에 바로 커밋한다. master는 직접 확인한 뒤에만 가져간다.
  • 작업마다 설계 단계. Opus 관점 둘(이번엔 슬라이스 설계 셋)을 메인 세션이 합쳐 결정하고, 코드 전에 기록한다.
  • 작업마다 리뷰. 정확성·규칙·스타일 세 렌즈의 읽기 전용 리뷰, 발견마다 반박하려는 검증자 하나. 확인된 발견은 다음 작업 전에 고친다.
  • 멈추는 곳은 둘. G1(무대가 섰다) — 이번 라운드에서는 멈추지 않고 보여만 주는 검토 지점으로 두었다 — 과 G2(직접 그 한 가지 작업을 해 보는 곳, 라운드의 끝). Mac은 멈추지 않는다: Metal 쪽은 눈 감고 쓰고, 확인할 것을 모아 둔다.
  • 규칙. 엔진(Engine/의 Sample 밖)에 Backlot 고유의 것은 없다. 텍스처·Masked·FBX처럼 기본 파이프라인이 가져야 할 기능은 엔진 작업이다. 모든 에디터 동작은 포트도 할 수 있는 속성 쓰기다.

컷별 골든과 Unity 비교 (stage-cuts) 완료

무대의 8컷이 이제 회귀 그림이다. Tools/stage_cuts는 낮과 밤 16장을 커밋된 골든과 비교한다. establishing의 낮은 smoke 골든과 비교하므로, 포트로 멈춰 찍은 프레임과 smoke가 자유롭게 돌다 찍은 60번째 프레임이 같다는 것을 매번 확인한다. 골든에는 그것을 찍은 Backlot 커밋이 스탬프로 붙는다. 에디터가 실제로 읽은 Backlot(editor.scene으로 되읽는다)이 그 커밋이 아니거나, 에디터가 읽는 파일에 커밋하지 않은 변경이 있으면 찍기만 하고 비교하지 않는다(exit 77). 아무것도 비교하지 않은 실행이 통과로 읽히는 일은 없다. -Record는 없거나 달라진 골든만 복사하고 커밋을 찍는다. ctest StageEditorCuts(Debug)로 돈다.

ImageCompare에는 가장자리 비교가 생겼다. 휘도에 Sobel을 걸고, 가장자리를 가로지르는 비최대 억제로 한 픽셀 폭으로 가늘게 만들고, 개수 예산으로 가장 강한 것만 남긴다. 그래서 톤 곡선, 블러, 밝기가 달라도 가장자리 자리는 움직이지 않는다. 결과로는 두 그림의 가장자리가 반경 안에서 서로를 찾는 비율, 가장 덜 맞는 타일, 정확히 겹치는 이동량이 나온다. 정수 연산뿐이라 Windows와 Mac이 같은 답을 내야 한다. -UnityRun은 컷마다 Unity의 같은 이름 그림과 비교해 오버레이, summary.tsv, report.html을 쓴다. 리포트에서 엔진 그림에 마우스를 올리면 Unity 그림과 번갈아 깜빡인다. 보고만 하고 종료 코드는 바꾸지 않는다.

Masked (masked) 완료

표준 파이프라인에 세 번째 머티리얼 도메인 Masked가 생겼다. 텍셀의 불투명도(알베도 텍셀의 alpha × 행의 opacity)가 행의 alphaCutoff에 닿으면 남기고, 못 미치면 잘라낸다. 색 패스, 깊이 프리패스, 그림자 맵에서 모두 잘린다. 깊이만 쓰는 패스에서는 Masked 머티리얼만 자기 maskShader(fs_masked_depth)를 프래그먼트 단계로 받는다. 블렌드도 셰이딩 모델도 없어서, 같은 방식으로 래스터라이즈하는 masked 머티리얼은 깊이 파이프라인 하나를 같이 쓴다. 두 진입점 모두 같은 loadSurface를 같은 uv로 읽으므로 프리패스와 색 패스가 같은 곳을 자른다.

Backlot에서는 SignAtlas 95장과 GameAtlas 35장, 쿼드 179장 중 130장이 0.5에서 잘린다. 사인 사각형의 투명 텍셀 자리에 이제 뒤의 벽이 보인다. alphaCutoff를 반사에 넣어서, 사인의 컷오프를 인스펙터와 포트로 똑같이 읽고 쓴다.

다시 읽기와 장면 시계 (editor-clock-reload) 완료

실행 중인 에디터가 장면 파일을 다시 읽는다. Backlot의 compose.py가 쓴 파일이든 한 줄을 고친 임시 사본이든, 다시 빌드할 필요가 없다. 다시 읽기는 두 단계다. 먼저 파일을 읽고, 실행할 때 로드한 것과 대조한다. 실행 시 로드하지 않은 모델이나 텍스처, 예약한 용량을 넘는 파일은 "재시작하면 로드된다"며 아무것도 바꾸지 않고 거부한다. 받아들이면 잡고 있던 손잡이, 선택 노출, 인스펙터 행을 모두 놓은 뒤 장면을 비우고 다시 채운다. 그다음 키와 시간을 다시 적용하고, 선택을 이름으로 다시 찾는다. 장면 시계는 실행할 때 0에서 멈춰 있다. Space로 재생하고, 화살표로 1/60초씩 움직이고, 포트로 시간을 쓰면 그 시점으로 간다. screen-ne의 플립북이 시간에 따라 칸을 넘긴다.

G1 · 무대가 섰다 검토 지점

StageEditor가 Backlot을 1920 × 1080으로 그린다. 8컷 모두, 낮·저녁·노을·밤 네 키 모두에서 모든 물체가 Unity 캡처(Captures/20261003-002425)와 같은 자리에 선다. 아래 시트의 세 번째 열은 50 % 블렌드로, 가장자리가 겹쳐 두 줄로 보이면 어긋난 것이다 — 어느 컷에도 없다.

다른 것은 스타일뿐이다: 하늘 그라데이션 대신 지평선 색 단색, URP 톤 매핑 대신 Reinhard, 블룸 없음. 그래서 엔진 쪽이 더 차갑고 어둡고, 밤의 발광이 덜 번진다. 이번 라운드의 범위 밖(키 보간·블룸·하늘·노출은 기록만)이다.

텍스처 완료

표준 파이프라인이 텍스처 모델을 그린다. RenderScene에 텍스처 표(텍스처와 정적 샘플러 하나), MaterialData 80 → 112 B(UV scale·offset, 발광 맵 ID, 알파 컷오프, 플래그를 뒤에 덧붙임), 맵 ID는 렌더러가 매 프레임 머티리얼의 핸들에서 쓴다(없거나 지워진 텍스처는 0). Forward 프로그램이 UV 변환을 거쳐 알베도·불투명도, 그다음 발광을 샘플하고, NoShadowReceive 머티리얼은 모든 라이트를 그림자 없이 받는다. 선형 샘플 텍스처는 CPU 밉 체인을 갖는다.

장면 파일 완료

SampleStage(샘플 라이브러리, 엔진 밖)가 Backlot의 scene.json을 타입 있는 행으로 읽는다: 미터와 도는 쓰인 그대로(인스펙터가 계약의 숫자를 보이도록), 색은 선형으로. 참조·축별 스케일·키가 빠뜨린 채널과 그룹·totals가 맞지 않으면 행을 짚어 거부한다. 스프라이트 매니페스트도 읽는다. loadStage가 모든 모델·텍스처·스프라이트를 CPU에 올리고 RenderApp이 잡아 둘 용량을 계산한다.

FBX 로더 완료

loadModel(Engine/Serialization, ufbx)이 FBX를 엔진 규약(왼손, +Y 위, 미터, 시계 방향 앞면, UV 원점 왼쪽 위)의 MeshData로, 머티리얼마다 슬롯 하나로 읽는다. 축 프로브의 표 — 경계, 삼각형 36개, 모두 앞면, 팔의 방향과 길이, 팔레트 색 — 를 엔진 저장소에 복사해 둔 픽스처로 검사하므로 Backlot 없이도 돈다.

위임 기록

  • 측정이 결정한 것. 슬라이스 설계와 계약 모두 reverse_winding = true를 권했지만, 측정에서 36개 삼각형이 전부 뒷면이 됐다. ufbx는 미러링된 메시의 인덱스를 스스로 뒤집고, 그 뒤집기가 FBX의 반시계 앞면을 시계로 만든다 — 옵션이 그걸 되돌리고 있었다. 이 실패가 그대로 앞면 판정 테스트의 red run이다.
  • 리뷰가 잡은 것. 그 사실을 거꾸로 적은 주석(고침), 함수 이름의 대소문자(loadModel).
